# 26.11.1

**Project:** KiraDB  
**Release week:** 2026-11-02 – 2026-11-08

## Highlights

## Durable synchronized streams

- Added `Value.Stream(id)` and `ColumnType.Stream` as first-class, non-keyable KiraDB values. Binary encoding uses the additive tag **8**, retaining compatibility with the original seven value tags, and table schemas persist the stream column type.
- Implemented append-only, durable text streams in `app/Streams/Streams.kira`: stable IDs, immutable ordered chunks, atomic chunk-and-cursor writes, open/completed/failed terminal states, incremental `readStreamSince` with the exact original chunk boundaries, and offline reopening. Repeated/out-of-order chunks, empty chunks, invalid cursors and writes after completion are rejected without changing stored data.
- Added `SyncServer.streamChange` for server-owned background generation. Recorded mutations commit atomically and call the same subscription transition logic as client mutations; connected replicas receive content and completion through their regular KiraDB sync protocol, never through a separate token buffer. A new end-to-end subscription test verifies live chunks, duplicate rejection and completed state on a replica.
- The SyncServer and the application's document layer can now share a single live reference-owned storage engine through `Database.fork()`, while keeping independent query/optimistic mutation recording contexts. A committed-write observer publishes server-owned KiraDB updates directly to subscribers. A regression test verifies shared committed data with isolated recordings.
- Fixed a general-purpose subscription equality bug: the replica compared abbreviated diagnostic `traceText` output, so two documents with the same number of fields (or two lists with the same number of entries) could incorrectly be treated as equal after their values changed. Subscriptions now compare the **complete encoded query outcome**, distinguishing values from errors as well. A regression test follows a same-shape document through `queued → running → completed` and verifies three separate change notifications.
- Added an opt-in **separate remote table catalog** for KiraDB replicas that share a database with an application's own local-only tables. Remote server catalog keys are replicated to the `sync-remote-catalog` keyspace, not the device's `c` catalog. Server subscriptions can resolve their remote table IDs, while local table queries retain their original IDs and offline-owned rows. `Replica.materializeTableQuery` and `Database.mirrorTableRows` reconcile a scoped server-owned partition into its named **local** table as one atomic batch; extra computed query fields are excluded, invalid/out-of-scope rows are rejected without partial writes, and unrelated partitions are preserved. This handles older servers whose table IDs changed during schema upgrades without a duplicate shadow table in the UI. A full SyncServer/Replica regression uses an independently recreated remote table and a fresh local table, proving the two IDs can differ and both contents remain readable.
- Corrected **subscription readiness on reconnected or previously populated replicas**. A `Changed` event from a cached local query is not proof that the server has confirmed the subscription's held key ranges. Previously, when the cache already equaled the server's result, no new event was delivered on readiness; clients that waited for server validation (including Harmony's Chat/Work capability selector) could remain stuck in their Chat-only fallback after reconnect. `ClientSubscription.readyReported` now causes exactly one notification on first readiness per connection even when the query bytes are unchanged, with the existing full-value change notifications retained. Reconnecting resets this readiness notification. A new regression starts with identical server/client query results and checks both the initial ready edge and reconnect.
- Added stream, shared-store, exact-value change detection, table-catalog isolation/mirroring, and unchanged-result readiness regression coverage. **43/43 KiraDB tests pass** with Kira 26.11.1.
